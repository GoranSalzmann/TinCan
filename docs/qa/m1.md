# M1 demo checklist

Everything below was run on 2026-10-28 except the VPS rows, which need your server and domain.
Cuts and deferrals: [18 §H](../18-open-questions-and-risks.md).

## A. Local checks (no Docker)

Needs Node 24+ and pnpm 12.

```bash
pnpm install
pnpm check
```

`pnpm check` = typecheck, lint, SPDX headers, all tests (unit, contract, module matrix, web), build, licence scan, secret scan.
Also: `node scripts/check-dco.mjs main` (every commit signed off).

- [ ] Contract suites pass for the DB (SQLite file and memory), storage (local), pubsub (memory) and auth (local).
- [ ] `pnpm test:matrix`: every module alone, the full set minus each module, and the refusal cases (missing dependency, `voice-e2ee` + `recording`, missing port, unknown module, stray setting).

## B. Deploy the compose stack (local trial, plain HTTP)

```bash
pnpm build
node apps/server/dist/cli.js init --dir ../tincan-trial --domain localhost --http-port 8081 --yes
cd ../tincan-trial && docker compose up -d --build
```

- [ ] `init` lists what it will write, then prints a setup token (also in `data/setup-token`).
- [ ] `docker compose ps`: `tincan` is healthy, `caddy` is up. `livekit` does not start (profile `voice`).
- [ ] `curl http://localhost:8081/api/v1/capabilities` answers JSON with `auth.setupRequired: true`.
- [ ] `curl -i http://localhost:8081/api/internal/x` answers 404 (blocked at the proxy).

## C. First run in the browser

- [ ] Open `http://localhost:8081/`. It redirects to `/setup` (step 1 of 4).
- [ ] A wrong token shows "That token doesn't match."; the right token moves on.
- [ ] Step 2: bad username or `password123` is refused with a field message; a long password is accepted and shows "Strong".
- [ ] Step 3: rename the community. Step 4: the WebSocket check says OK; HTTPS says "Not working" with a warning (expected over plain HTTP); voice says "Skipped".
- [ ] Finish opens the empty layout: channel list ("No channels yet"), "Welcome" header, member list, you at the bottom, a "Connected" indicator.
- [ ] `data/setup-token` is gone. Reload the page: still logged in. `/setup` redirects back to `/`.
- [ ] Account menu → Log out returns to the login screen; log in again with the same account.
- [ ] Wrong password shows one generic message; the 6th quick attempt shows a countdown and disables the button.
- [ ] Server menu → Appearance: Light / Dark / High contrast / accents change the colours at once and survive a reload.
- [ ] Keyboard: Tab reaches "Skip to main content" first; F6 cycles channel list → main → member list; focus rings are visible.

## D. Operations

```bash
node apps/server/dist/cli.js doctor --config ../tincan-trial/config.yaml --url http://localhost:8081
node apps/server/dist/cli.js config check --config ../tincan-trial/config.yaml
node apps/server/dist/cli.js module list --config ../tincan-trial/config.yaml
```

(`config check` and `doctor` need `TINCAN_SECURITY__INSTANCE_SECRET` from `.env` in the environment.)

- [ ] `doctor`: configuration, data directory, disk, memory, DNS, HTTPS/proxy and WebSocket are `[ok]`; voice rows are `[--]`.
- [ ] `docker compose restart tincan`, then reload the browser: still logged in; the status returns to "Connected".
- [ ] `docker compose down -v` removes everything.

## E. On a real VPS (needs you)

- [ ] DNS A record, ports 80/443 open; `init --domain chat.example.com --email you@example.com`; `docker compose up -d --build` (images are built from the checkout until releases exist).
- [ ] `https://chat.example.com/setup` works with a Let's Encrypt certificate; the HTTPS check in step 4 is OK.
- [ ] `tincan doctor` from your own machine against the public URL is all `[ok]`.
